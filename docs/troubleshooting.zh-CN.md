# 常见问题

## 页面没有出现悬浮栏

先确认页面加载的是部署后的脚本：

    npm run verify:deploy

然后刷新 http://localhost:5001/。如果仍然没有出现，检查本地 Excalidraw 的 index.html 是否引用了 /recorder/studio-recorder.js。

## 新增幻灯片没有鸟瞰

打开白板控制 -> 设置，确认“新增后全局鸟瞰”开启。当前版本会默认开启该选项。

## 修改后页面还是旧效果

执行：

    npm run deploy:local
    npm run verify:deploy

然后强制刷新浏览器页面。

## 仓库和部署目录不一致

执行：

    npm run verify:deploy

如果失败，重新执行：

    npm run deploy:local

如果你临时直接改了运行目录，先执行：

    npm run sync:from-live

再提交 Git。

## 录制视频有问题

录制问题需要按真实组合验证：

- 屏幕/窗口录制
- 白板录制
- 当前幻灯片录制
- 摄像头是否合成进视频
- 不同画幅和摄像头尺寸

不要只看按钮状态或页面提示，要实际下载并播放视频确认。

## 打开文件后项目内容不完整

确认使用了正确入口：

- “打开项目文件夹…”会读取完整项目、白板、录制和编辑状态；
- “打开 Excalidraw 文件…”只读取一个白板文件，不会自动附带录制、逐字稿或字幕。

“设置项目文件夹…”用于建立新项目根：当前白板与讲稿会保留，但上一项目的录制、逐字稿、字幕和编辑决策不会被带入。继续已有项目时应使用“打开项目文件夹…”。

项目内路径必须是相对路径。不要手工把 `recordings/` 或 `text/` 移到项目根之外。

## 自动逐字稿不可用

先运行：

    npm run setup:asr

确认本地运行目录中存在 `.venv-asr`，再重启本地服务。逐字稿必须来自实际录音；提词稿只用于术语上下文，不能代替 ASR。

## 导出成片失败

先确认项目已选择本地文件夹，原始录制路径存在，并检查：

    npm run verify:deploy

成片固定写入项目的 `exports/final.mp4`。如果渲染中断，可重新点击“导出成片”；原始录制和时间线不会被覆盖。

macOS 的硬件 H.264 编码器偶尔会被其他应用占用。v0.1.1 导出链路会先尝试 VideoToolbox，并在硬件编码失败时自动回退到软件 H.264；如果仍然失败，再检查 FFmpeg 是否完整安装。

## 摄像头位置修改没有作用

查看录后编辑器中的能力提示。当前 Native Capture Agent 可能已经把摄像头烧入混合原片，此时只能整体处理，无法在录后重新拆层。只有项目中存在真实独立摄像头素材时，位置、大小和镜像设置才会完整生效。
